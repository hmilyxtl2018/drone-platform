开源情报到本体知识：目标输出与修订计划

日期：2026-10-08。当前任务：战术无人机的协同能力趋势分析。

目标

把采编结果变成可追溯、可核验、可逐项审核并可供后续 Agent 读取的本体知识。大模型承担对象识别、属性和值提取、关系与事件提议以及趋势分析；采集工具取得资料；程序核对引用和版本；人审核语义、证据与准入。

完成标准是“来源 → 对象 → 属性／关系／事件断言 → 证据核验 → 人工审核 → 本体版本 → 可回读”，并能从一条趋势判断追到它所依赖的对象属性和原始材料。

用户看到的五个视图

  • 采编执行：任务题目与点击式提示词图标；查询计划、来源范围、真实工具调用与实际模型；正文、来源图片与卫星影像分别展示，保留与过滤理由明确。未执行、失败、超预算和零相关结果都显示真实状态。
  • 对象分析：每个装备型号、技术、组织、项目和公开事件都有详情。属性以“中文属性名／规范值／原文值／单位与条件／证据性质／核验状态”排列；点击任一属性打开原文与位置。关联关系和事件保留自己的证据，不把页面共现当成技术采用关系。每个对象都有属性提取状态与缺口。
  • 图谱洞察：按对象类别区分节点；按关系类型与核验状态筛选。点击边可见断言及来源，点击对象可见属性与关联事件；研究关联、模型推测和人工确认事实有明确状态，不从共现推导因果。
  • 趋势研判：每项判断表达“哪些对象、哪种公开特征、变化方向、时间视界、支持证据、相反证据、适用条件、不确定性与补证任务”。只有有可比数据的指标才绘制数值趋势；材料条数不能当能力曲线。出处检查、对象归属、来源独立性、反证检查与人工核验关联到具体断言。
  • 洞察结论与本体准入：展示模型建议采纳／保留草稿／补证／退回的对象及属性，逐项列出理由和依据。审核人可以改值、补证和拒绝；审核后写入明确的本体类别、属性谓词、关系及版本，可在知识库回读并追溯来源。

属性目标结构

  • 身份与版本：assertionId, objectId, objectRevision, attributeKey, ontologyPredicate。未完成本体映射的属性保持研究草稿。
  • 数据值：rawValue, normalizedValue, valueType, rawUnit, normalizedUnit, conditions。模型翻译和规范化与原文分开；数值转换记录规则并接受审核，不能用常识补造缺失值。
  • 事实性质：claimKind 区分厂商自述、项目目标、公开报道试验、采购记录和分析推断。分析推断不得伪装为直接提取事实。
  • 证据：evidenceRefs[] 内含 sourceItemId, sourceUrl, sourceVersion, contentHash, quote, startChar, endChar；属性归属证据可与名称身份引用分开。
  • 时间：资料发布日期、公开事件日期、事实有效时间分别记录；影像另记采集日期，未知保留未知。
  • 状态：extractionStatus, locatorCheck, attributionCheck, independenceStatus, modelConfidence, reviewStatus, reviewedConfidence，审核记录含审核人、理由与时间。

来源可靠性、具体属性可信度与趋势结论置信度分开。调用模型次数、不同 URL 数量或有图片均不能自动提升任何一项。

已确认的问题与边界

  • 检索相关性：旧检索过宽，原报告选择的四条资料中混有民航背景和长篇目录；技术名 INTeACT 来自非无人机主题的厂商资料。需要主题与对象两层筛选，背景材料保留其角色，不充作型号属性证据。
  • 正文覆盖：旧 5,000 字符窗口没发送 Airbus 保存全文中约第 6,500 字符后的 XQ-58A 与架构描述段。新选段已改善，但保存正文上限及每步窗口预算仍然影响覆盖。
  • 属性任务不足：此前确实调用了 DeepSeek；对象、属性、关系共用一次输出，提示词每对象只优先三项属性。原始值或对象上下文不满足校验时被过滤；没有保存失败提议，不能确定具体是哪一项条件失败，也不能据此声称来源未披露。
  • 状态解释不足：空属性列表混合了未读取、无明确披露、模型遗漏、调用失败和校验拒绝，用户无法定位下一步。
  • 影像检索口径：旧图片查询附加了软件属性词与 archive／采集日期硬条件；已经修正并接入 Firecrawl v2 图片搜索。最近五条候选均不匹配 XQ-58A，未取得相关卫星影像。这是本次证据缺口，不足以断定整个搜索服务失效。
  • 本体属性链断点：当前对象准入的 assertion.attributes 对普通实体仍为空，事件仅保留 eventKind。即使分析页面有属性，也不等于属性已经写入可信知识库。

依次执行的工作包

P0：固定验收样本与输出合同

保存当前材料、报告、图谱版本及失败记录；明确对象类别的建议属性模板、规范值与原文值、断言性质及字段状态。用保存原文建立已知可提取属性、错误对象归属和无披露字段的样本。

交付：样本清单、Schema、字段状态定义、验收基线。验收：模型未提取不能被标为“来源无披露”；本体属性映射尚未建立时不能显示“可直接入库”。

P1：逐对象大模型提取及对象定向上下文

识别身份后固定 objectId、类别与身份引用；针对每个对象的命名段、定义段、相邻解释和有关公开事件生成原文窗口。逐对象提取属性和值并记录每项自己的引文、原文值与规范化展示值。每对象最多十二项；每批最多八个对象，剩余进入下一批或明确显示未执行。

出处校验保持严格；增加原文恢复、对象归属与状态解释，而不是为提高数量放宽事实依据。受预算或截断影响时标为未覆盖；只有实际阅读范围没有明确属性时，才标记该范围内无明确披露。失败提议保存为诊断草稿，不进入已核对属性集合。

交付：逐对象属性草稿、字段覆盖记录、失败与拒绝原因。验收：已知可提取属性能在真实 DeepSeek 调用后保留；对象身份和旧有效属性不因一次失败丢失；每个对象有明确处理状态。

P2：缺口驱动补采与影像补证

围绕“对象＋具体待核验属性／公开事件”生成补采计划，优先军方公开项目、独立试验评估和原始文件，厂商自述分开。影像按公开历史资料或已公开事件补证；允许通过有证据的公开事件关联到对象，不要求图片标题必须出现型号名，也不接受无法说明关联的图片。

每条影像记录原始提供方、采集日期、发布日期、许可、可见内容、解释、支撑命题与局限。卫星影像与来源照片分开，未知类别不自动分类。多个转载同一影像不能算多个独立来源，影像不能证明接口互操作或协同效能。

交付：新证据、来源独立性记录、影像与断言关联或明确零结果。验收：每次补采都有对象、问题、预算和停止条件，错误类型与无关候选不会补量充数。

P3：异步执行、五个视图和逐项人工核验

每个对象的提取、校验、失败和补采状态进入可恢复任务；展示实际模型、耗时与调用状态。属性候选先落批次草稿，核对版本后合并新图谱，避免旧审核静默绑定到新对象。

前端显示原文与规范值、归属条件、证据性质和状态；模型给出“建议接受／补证／退回”及理由。用户可确认、修改、补证或拒绝具体属性，不必只接受整份报告。核验与趋势判断均回指属性、关系和事件。

交付：交互与异步任务。验收：任务切换、报告切换、图谱更新、部分失败和刷新恢复不会误挂证据或丢审核记录。

P4：本体属性准入与闭环验证

扩展现有对象／准入 JSON Schema 与 TBox 属性映射；为待准入属性保留独立证据、人工审核和有效时间。需要新属性定义时先审类别与谓词，再审断言；不将任意模型字段直接写入本体。兼容现有 SQLite／JSON 记录，按版本和查询需求确定必要的附加表，不重建整个数据库。

交付：对象与属性候选、关系／事件准入、发布版本与知识库读取。验收：公开示例中的一条有效属性从实际采编与 DeepSeek 提取，经过人工审核写入本体后能回读，原文、版本、限定条件仍完整；未经审核的属性不发布。

P5：完整运行链回归与演示

对当前主题执行一次有限预算的真实采编与提取；记录 Firecrawl v2 图片调用和 DeepSeek 实际返回模型。覆盖跨来源属性、错误归属、来源冲突、部分模型失败、未知字段、没有相关影像及图谱版本变化。

交付：结果对照、执行记录、测试报告与可预览页面。验收按事实质量与链路完整性，不按必须有多少型号、属性或卫星图判断成功。每条保留断言都可追溯，每个缺口都能解释且有明确下一步。

当前实施状态

P0–P5 功能实现与有限预算运行验收已完成；真实知识断言仍待逐项人工审核。 已接通逐对象属性提取、可恢复后台任务、五个视图、按具体属性缺口生成的有限预算补采、公开历史影像的冻结对象关联，以及逐属性修改、审核、准入和知识库回读链路。图谱支持对象类别、关系类型与审核状态组合筛选，节点属性可跳转到绑定图谱版本的具体引文。模型建议、出处检查与人工核验分别记录。

真实运行已确认返回模型为 deepseek-v4-pro，最后一轮 MARS 重试的两次调用均返回该模型。最终图谱为修订 9（graph-revision-1e0cadfb12e8473a），包含 8 个对象（3 个技术、3 个组织、2 个装备型号）、8 项属性和 8 条趋势属性引用。MARS Mission System 的架构原文值 modular, open architecture solution 已保留为待审核草案，原文位置、来源版本和哈希可追溯。部分调用失败时，旧有效属性与失败状态保留。

这 8 项属性并不意味着语义均已确认：历史 OODA 草案保留原值，其 human-oversight 类别检查已明确标为失败，需修正分类、补证或退回；架构属性自身机器检查通过，可以独立审核，不受同对象其他属性失败影响。真实环境只生成对象身份和架构属性两个 under-review 准入候选，均未接受、未发布。连续引文恢复仍标为待人工确认对象归属，不能替代语义判断或独立来源核验。

本轮 Firecrawl v2 图片检索返回 8 条原始候选，均因对象或公开事件不匹配被过滤，保留相关影像 0 条。官方评估来源另有 1 次超时，4 条正文候选经相关性检查后全部过滤，保留 0 条。没有用普通照片或无关材料补量，也没有因此提高置信度；相关卫星影像与独立佐证仍是明确缺口。

逐属性准入到知识库回读已通过 8 项隔离端到端检查，使用实际架构属性及测试审核人模拟操作，没有替用户审核或向真实本体库发布。最终全量后端 294 项测试通过（39.089 秒），前端 27 项 VM 交互检查与 JavaScript 语法检查通过，11 项 HTTP 检查通过（前端资源版本 v26）。以上验证覆盖程序约束、状态恢复、历史分类失败隔离与证据回读；没有进行浏览器视觉验收，也不代表来源独立性、事实语义或装备能力已经获得确认。
